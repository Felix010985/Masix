# AGENTS.md

Заметки для автоагентов и для всех, кто работает с этим деревом. Относится по факту
к **тестовому репозиторию с кодовым именем `MazokOS`**, где ядро **Masix**
активно вайбкодится. Основной (mainline) репозиторий - человеческий, но может принять автоизменения 
при условии контроля со стороны контрибьютора.

> [!NOTE]
> **Всё меняется.** Внутренние API, ABI системных вызовов, набор драйверов,
> структура каталогов и правила сборки - не стабильны. Перед правкой
> **сверяйся с текущим кодом**, а не с этим документом: он описывает
> договорённости, а не контракт.

## Что это за проект

- Монолитное POSIX/Linux-совместимое ядро
- Полностью свободностоящее: `-ffreestanding -nostdlib`,.
- Сборка: `clang` + `ld.lld`, скрипт линкера -
  `sys/kernel/arch/x86/i686/linker.ld`.

## Жёсткие правила

1. **Разделение по разрядности (важно).**
   - `sys/kernel/arch/x86/` - код, **общий для 32 и 64 бит**.
   - `sys/kernel/arch/x86/i686/` - то, что зависит от разрядности: переход в
     реальный режим, 32-битные таблицы EFI, 32-битный paging, GDT/IDT/TSS,
     VBE.
   - **Не переносить файлы по имени.** Классифицируй по содержимому: если код
     не трогает 32-битную специфику - он общий и живёт в `arch/x86/`.
2. **Изоляция драйверов.** Аппаратный код - в `sys/kernel/drivers/`, публичные
   интерфейсы - в `sys/kernel/drivers/include/drivers/<имя>.h`. VFS и devtmpfs
   не обращаются к символам драйверов напрямую: зависимость идёт **от
   драйвера к VFS**, а не наоборот (`vfs_register_device`).
3. **Отладочный вывод - только `debug_puts()`** (см. `sys/kernel/include/config.h`).
   Бэкенд выбирается макросом (`DEBUG_OUTPUT_SERIAL` по умолчанию - COM1).
   Напрямую звать `serial_puts()` из нового кода не нужно.
4. **Заголовок файла.** Каждый исходник начинается с
   `/* SPDX-License-Identifier: GPL-2.0-only */` и блока с копирайтом.
5. **Комментарии - по-русски.** Стиль - спокойное объяснение «почему», а не
   пересказ «что». Такой же язык у сообщений коммитов и документации. Повествование ведётся от лица ядра!
6. **Никаких новых внешних зависимостей** в ядре без явной необходимости.
   Хостовые утилиты сборки живут в `tools/`.
7. **Не считать отладочные артефакты нормой.** `debug_puts` в горячих местах
   и временные проверки - добавлять осознанно и убирать за собой.

## Стиль кода

- Отступ - **4 пробела**, скобки в стиле K&R, `if (...)` с пробелом.
- Имена: `snake_case` для функций и переменных, `SCREAMING_SNAKE_CASE` для
  макросов/констант, `_t` для типов.
- Публичные функции отражают путь к файлу: `multiboot2_gather()`,
  `linux_gather()`, `limine_gather()`.
- Внутренние функции - `static`.
- Компилятор должен собирать код **без новых предупреждений** (`-Wall -Wextra`).

## ABI системных вызовов

- Вход: `int $0x80`, номер в `eax`, аргументы в `ebx/ecx/edx/esi/edi`.
- Выход: результат в `eax`; отрицательное значение - код ошибки.
- Номера совпадают с **Linux i386** и продублированы в
  `sys/kernel/include/syscall.h` (ядро) и `bootstrap/src/syscall.h` (юзерленд).
- Новый вызов добавляется в `syscall_handler_c()` в `sys/kernel/syscall.c`;
  хэндлеры-заглушки возвращают `-LINUX_ENOSYS`.
- Реализация высокоуровневых обёрток (структуры, копирование в/из
  пользователя) - в `sys/kernel/uapi.c`, объявления - в
  `sys/kernel/include/uapi.h`.

## Сборка и проверка

```bash
cc tools/configure.c -o conf && ./conf   # сгенерировать config.mk
make                                     # ядро + bootstrap + initramfs
make iso                                 # загрузочный образ
make run                                 # запуск в QEMU
make clean                               # очистка build/
```

Перед завершением работы **обязательно собрать** проект и убедиться, что нет
новых ошибок/предупреждений:

```bash
make 2>&1 | grep -iE "error|warning" | grep -v pmm.c
```

## Тестирование в QEMU

- Ядро пишет лог в **COM1**, поэтому удобно запускать headless:
  ```bash
  qemu-system-i386 -cdrom build/mazukios.iso -m 256M -display none \
    -serial file:/tmp/run.log -nic user,model=rtl8139 -no-reboot -no-shutdown
  ```
- Ввод тоже можно гонять через COM1: обработчик IRQ4 кладёт байты в общую
  очередь ввода консоли (`keyboard_push_char`). Удобно через `-serial pipe:`
  (QEMU создаёт `<path>.in` и `<path>.out`).
- Экран снимается монитором QEMU: `screendump /tmp/screen.ppm`.
- Полезная трассировка: `-d in_asm -D /tmp/asm.log` или `-d in_asm,int`.
- Маркеры успешной загрузки: `linear framebuffer is ready`,
  `Multitasking started! Jumping to Ring 3...`,
  `sys_execve switch complete!`.

## Известные ловушки

- **Реальный режим (`realmode.c`).** BIOS восстанавливает `CS` как
  `sel*16`, поэтому база 16-битного дескриптора кода **обязана** совпадать с
  селектором. Восстанавливать `CR3`/`CR4` нужно **до** `CR0`, иначе первый
  fetch уйдёт в пустой каталог страниц. ESP вызывающего сохраняется/восстанавливается.
- **Окно MMIO.** `VMM_MMIO_BASE = 0xE8000000`, размер `VMM_MMIO_SIZE = 16 МБ`.
  `vmm_map_mmio()` выделяет **отдельную таблицу страниц на каждые 4 МБ**;
  одной таблицы на всё окно не хватает.
- **Порядок с PIC.** Вектор IRQ = база PIC (`0x20`) + линия. Регистрировать
  обработчики и разрешать прерывания нужно **после** `pic_init()`, иначе
  прерывание уйдёт на чужой вектор.
- **Ориентиры ввода:** IRQ0 - PIT, IRQ1 - клавиатура, IRQ4 - COM1.
