# AGENTS.md

Указания для автоматизированных агентов.

Правила проекта, стиль кода, сборка, тестирование описаны
в [`PEOPLE.md`](PEOPLE.md). Процесс контрибьюта - в
[`CONTRIBUTING.md`](CONTRIBUTING.md). При расхождении документации и кода
приоритет у текущего кода.

## Контекст

- Mainline обновляется после проверки изменений контрибьютором.
- Внутренние API, ABI системных вызовов, драйверы, структура каталогов и
  правила сборки не стабильны.
- ИИ-инструменты допускаются в тестовом репозитории. Автоматические
  изменения в mainline принимаются только после проверки контрибьютором.

## Перед изменением

- Прочитать текущий код в затронутой подсистеме, не полагаться только на
  документацию.
- Проверить `git status` и `git diff`: в дереве могут быть незакоммиченные
  правки других участников.
- Классифицировать файлы `arch/x86` по содержимому, а не по имени.
- Учитывать изоляцию драйверов: зависимости идут от драйвера к VFS, не
  наоборот.
- Сверяться с ABI системных вызовов в `PEOPLE.md` при добавлении вызова.

## Обязательные требования

- Соблюдать стиль кода и правила из `PEOPLE.md`: отступ 4 пробела, K&R,
  `snake_case`, заголовок SPDX с копирайтом, комментарии по-русски с
  объяснением причины.
- Использовать `debug_puts()` вместо прямых вызовов `serial_puts()`.
- Не оставлять временные отладочные проверки и лишний `debug_puts()` в
  горячих местах.
- Не добавлять внешние зависимости в ядро без необходимости.
- Не коммитить без явного запроса.
- Не удалять и не переписывать историю без явной просьбы.
- Не затирать чужие незакоммиченные изменения.

## Проверка перед завершением

Собрать проект и убедиться, что нет новых ошибок и предупреждений:

```bash
make 2>&1 | grep -iE "error|warning" | grep -v pmm.c
```

При изменениях загрузки, памяти, драйверов или системных вызовов проверить
запуск в QEMU по инструкции из `PEOPLE.md`.
