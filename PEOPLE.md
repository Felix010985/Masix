# PEOPLE.md

Документ для людей, работающих с репозиторием: разработчиков, контрибьюторов
и ревьюеров.

## О проекте

- Монолитное Маякойка | POSIX/Linux-совместимое ядро.
- Полностью свободностоящее: `-ffreestanding -nostdlib`.
- Сборка: `clang` + `ld.lld`.
- Скрипт линкера: `sys/kernel/arch/x86/i686/linker.ld`. (таргет пока что один, i686)

Внутренние API, ABI системных вызовов, набор драйверов, структура каталогов и
правила сборки не стабильны. При работе с кодом ориентируйся на текущее
состояние дерева, а не на документацию.

## Правила кода

1. **Разделение по разрядности.**
   - `sys/kernel/arch/x86/` - код, общий для 32 и 64 бит.
   - `sys/kernel/arch/x86/i686/` - код, зависящий от разрядности: переход в
     реальный режим, 32-битные таблицы EFI, 32-битный paging, GDT/IDT/TSS,
     VBE.
   - Файлы не переносятся по имени. Классификация идёт по содержимому: если
     код не использует 32-битную специфику, он относится к `arch/x86/`.
2. **Изоляция драйверов.** Аппаратный код находится в `sys/kernel/drivers/`,
   публичные интерфейсы - в `sys/kernel/drivers/include/drivers/<имя>.h`.
   VFS и devtmpfs не обращаются к символам драйверов напрямую. Зависимость
   идёт от драйвера к VFS через `vfs_register_device()`.
3. **Отладочный вывод.** Используется `debug_puts()` из
   `sys/kernel/include/config.h`. Бэкенд выбирается макросом
   (`DEBUG_OUTPUT_SERIAL` по умолчанию, COM1). Вызывать `serial_puts()`
   напрямую в новом коде не нужно.
4. **Заголовок файла.** Каждый исходник начинается с
   `/* SPDX-License-Identifier: GPL-2.0-only */` и блока с копирайтом.
5. **Комментарии.** Пишутся по-русски. Комментарий объясняет, почему решение
   принято, а не пересказывает соседнюю строку. На русском также пишутся
   сообщения коммитов и документация.
6. **Внешние зависимости.** Новые зависимости в ядре не добавляются без
   необходимости. Хостовые утилиты сборки находятся в `tools/`.
7. **Отладочные артефакты.** `debug_puts()` в горячих местах и временные
   проверки добавляются осознанно и удаляются после отладки.

## Стиль кода

- Отступ - 4 пробела, скобки в стиле K&R, `if (...)` с пробелом.
- `snake_case` для функций и переменных, `SCREAMING_SNAKE_CASE` для макросов
  и констант, суффикс `_t` для типов.
- Публичные функции отражают путь к файлу: `multiboot2_gather()`,
  `linux_gather()`, `limine_gather()`.
- Внутренние функции объявляются `static`.
- Код должен собираться без новых предупреждений (`-Wall -Wextra`).

## ABI системных вызовов

- Вход: `int $0x80`, номер вызова в `eax`, аргументы в `ebx/ecx/edx/esi/edi`.
- Выход: результат в `eax`. Отрицательное значение - код ошибки.
- Номера совпадают с Linux i386 и продублированы в
  `sys/kernel/arch/x86/i686/include/syscall.h` (ядро) и
  `bootstrap/src/syscall.h` (юзерленд).
- Новый вызов добавляется в `syscall_handler_c()` в
  `sys/kernel/arch/x86/i686/syscall.c`. Заглушки возвращают
  `-LINUX_ENOSYS`.
- Высокоуровневые обёртки (структуры, копирование в/из пользователя)
  реализуются в `sys/kernel/arch/x86/i686/uapi.c`, объявления - в
  `sys/kernel/arch/x86/i686/include/uapi.h`.

## Сборка и проверка

```bash
cc tools/configure.c -o conf && ./conf   # сгенерировать config.mk
make                                     # ядро + bootstrap + initramfs
make iso                                 # загрузочный образ
make run                                 # запуск в QEMU
make clean                               # очистка build/
```

Перед завершением работы проект собирается, и проверяется отсутствие новых
ошибок и предупреждений:

```bash
make 2>&1 | grep -iE "error|warning" | grep -v pmm.c
```

## Тестирование в QEMU

Ядро пишет лог в COM1, поэтому запуск удобно выполнять без графики:

```bash
qemu-system-x86_64 -cdrom build/masix.iso -m 256M -display none \
  -serial file:/tmp/run.log -nic user,model=rtl8139 -no-reboot -no-shutdown
```

- Ввод можно передавать через COM1: обработчик IRQ4 кладёт байты в общую
  очередь ввода консоли (`keyboard_push_char`). Для этого подходит
  `-serial pipe:` (QEMU создаёт `<path>.in` и `<path>.out`).
- Экран снимается монитором QEMU: `screendump /tmp/screen.ppm`.
- Трассировка: `-d in_asm -D /tmp/asm.log` или `-d in_asm,int`.
- Маркеры успешной загрузки: `linear framebuffer is ready`,
  `Multitasking started! Jumping to Ring 3...`,
  `sys_execve switch complete!`.

## Использование ИИ

ИИ-инструменты допускаются в тестовом репозитории. В mainline изменения,
сделанные автоматически, принимаются только после проверки контрибьютором, ИИ комментарии в коде разрешены, они помогают документировать Masix.
