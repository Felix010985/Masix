# Как контрибьютить в Masix

Спасибо за интерес к проекту! **Masix** - независимое POSIX-совместимое ядро, 
которое пишется с нуля. Любая помощь приветствуется: код,
драйверы, файловые системы, документация и обзоры.

> [!WARNING]
> **Всё в проекте - в активной разработке.** Внутренние API, ABI системных
> вызовов, набор драйверов и структура каталогов могут меняться без
> предупреждения. Прежде чем опираться на что-то, сверься с актуальным кодом.

## Прежде чем начать

Проект распространяется под лицензией **GPL-2.0-only** (см. заголовок
`SPDX-License-Identifier` в начале каждого файла). Отправляя изменения, ты
соглашаешься с этими условиями.

В будущем планируется своя лицензия, так что проект может перелицензироваться в любой момент!

Если сомневаешься в чём-то или собираешься сделать крупную правку -
**сначала открой issue** и опиши задумку, чтобы не потратить работу впустую, так как testing репозиторий 
порой не обновляется неделями, он может активно вайбкодится или рефракторится.

## Сборка

```bash
cc tools/configure.c -o conf   # собрать конфигуратор
./conf                         # сгенерировать config.mk
make                           # ядро + bootstrap + initramfs
make iso                       # загрузочный ISO
make run                       # запуск в QEMU (для тестов only)
```

Требования: `clang`, `ld.lld`, `grub-mkrescue`, `qemu-system-x86_64`, `cpio`,
`objcopy`.

## Правила кода

- **Отступ - 4 пробела**, скобки в стиле K&R, имена в `snake_case`,
  константы в `SCREAMING_SNAKE_CASE`, типы с суффиксом `_t`, для каждой функции ее 
  префикс это название файла, есть пару редких исключений в `uapi.c`.
- Каждый исходник начинается с `/* SPDX-License-Identifier: GPL-2.0-only */`
  и блока копирайта.
- Ядро полностью свободностоящее: **никакой libc**. Не тяни в ядро внешние
  зависимости без крайней необходимости.
- Разделение по разрядности: общий для 32/64 бит код - в
  `sys/kernel/arch/x86/`, зависящий от разрядности - в
  `sys/kernel/arch/x86/i686/`. **Не переносить файлы по имени** - решай по
  содержимому.
- Драйверы изолированы в `sys/kernel/drivers/`, публичные интерфейсы - в
  `sys/kernel/drivers/include/drivers/`.
- Отладочный вывод - только через `debug_puts()`.

## Про комментарии

Решение оснащать код комментариями не было спонтанным: ядро **Masix** уже
слишком велико, чтобы полагаться на короткие заметки вида
`// вот тут делается вот это`. Комментарии пишутся в первую очередь ради
удобства тех, кто захочет помочь проекту дойти до целей.

Многим комментарии не нравятся, многие считают их слишком «влажными» для
серьёзного кода или ассоциируют их с низкосортным машинно-сгенерированным
кодом. Мы это понимаем - но это вынужденная мера для поддержания внутренней
чистоты кода, даже если за неё придётся заплатить килобайтами места в
репозитории. Спасибо за понимание!

Хороший комментарий объясняет **почему** так сделано, а не пересказывает
**что** делает соседняя строка.

## Тестирование

Перед отправкой изменений **обязательно собери проект** и убедись, что нет
новых ошибок и предупреждений:

```bash
make 2>&1 | grep -iE "error|warning"
```

Полезно также прогнать ядро в QEMU. Лог ядра идёт в **COM1**, поэтому удобно
запускать headless:

```bash
qemu-system-i386 -cdrom build/mazukios.iso -m 256M -display none \
  -serial file:/tmp/run.log -nic user,model=rtl8139 -no-reboot -no-shutdown
```

Маркеры успешной загрузки: `linear framebuffer is ready`,
`Multitasking started! Jumping to Ring 3...`,
`sys_execve switch complete!`. Подробнее про отладку - в
[`AGENTS.md`](AGENTS.md).

## Как предложить изменение

1. Сделай отдельную ветку под свою правку.
2. Держи коммиты небольшими и логичными; заголовок в стиле `fix: ...` или
   `feat: ...`, в теле - суть и зачем.
3. Опиши в PR, **что** меняется и **как** это проверено.
4. Не затирай чужие незакоммиченные изменения: сначала посмотри
   `git status` и `git diff`.
